03 · Progressive disclosure

Everything is reachable. Almost nothing is permanent.

The Canvas uses four visibility levels. This creates depth without turning the workspace into an airplane cockpit.

LEVEL 1●

Always visible

Project and lifecycle status, View/Edit, device, undo/redo, AI composer, one primary next action.

LEVEL 2◉

Selection contextual

Content, layout, tokens, assets, motion, destination, accessibility, and evidence status for the selected object.

LEVEL 3◎

On-demand drawers

Pages, layers, references, research, asset library, history, checkpoints, and quality issues.

LEVEL 4○

Separate surfaces

Client review, agency qualification, deployment, and future Web-app runtime stay outside the core mutation workspace.

RESPONSIVE BEHAVIOR

Desktop, tablet, and mobile use real iframe widths. Touch layouts shift drawers into bottom sheets and raise controls to 44px.

CROWDING RULE
1
drawer open at a time

A new tool replaces the previous drawer. Context remains stable through selection chips and history.

01

Project and run home

Find, understand, and resume any local project run.
Run-state foundationExpanded library
  • Run library with labels, lifecycle state, layout authority, cost, last activity, and filters.
  • Resume, evidence, preview, review, and qualification entry actions.

02

Workspace modes

Separate experiencing the site from changing it.
View and EditLifecycle modes
  • View mode preserves navigation, buttons, hover states, animation, WebGL, parallax, and scroll behavior.
  • Edit mode overlays safe selection and controls without changing the site source directly.
  • Design, Client Review, and Qualify are distinct lifecycle modes with different permissions.
  • Client review and qualification remain separate from the core mutation UI.
03

Canvas shell and navigation

Move through pages, layers, and viewports without losing the site.
Core shellWorkspace tabs
  • Pan, zoom, center, fit, and reset controls.
  • Page and layer navigation with collapsible left rail.
  • True desktop, tablet, and mobile iframe viewports with breakpoint indicator.
  • Collapsible inspector and full-canvas focus mode.
  • Multi-tab workspace and captured-reference tabs remain draft, not binding.
04

Selection and hierarchy

Target every editable object through a stable identity.
Page IR source authority
  • Select sections and supported descendants, including text, links, buttons, images, containers, and decorative layers.
  • Stable editor IDs survive compile and connect comments, history, and mutations.
  • Parent, child, previous, and next navigation expose hierarchy.
  • Selection, text edit, drag, and preview states remain visually distinct.
  • For page-ir-v1, Page IR remains the editable source of truth.
05

Content and actions

Edit copy and behavior through validated capabilities.
Typed mutation
  • Add, delete, replace, and revise supported text.
  • Edit button labels, links, destinations, and appointment actions.
  • Copy checks cover evidence binding, promise strength, overflow, headings, and accessibility.
  • Changes compile a private candidate and update the visible version only after affected gates pass.
  • Rejected edits leave the accepted candidate and gate receipt unchanged.
06

Layout and responsive control

Shape composition without exposing arbitrary code.
Bounded layoutCompare mode
  • Stack, flex, grid, spacing, sizing, alignment, and bounded positioning.
  • Per-breakpoint behavior for desktop, tablet, and mobile.
  • Side-by-side responsive comparison with linked selection is a proposed expansion.
  • No arbitrary raw CSS, class injection, or unsupported DOM patching by default.
  • Unsupported capabilities are stated clearly instead of silently approximated.
07

Tokens and design system

Change a site consistently, with scope and impact visible.
Semantic token system
  • Typography, color, spacing, radius, border, shadow, breakpoint, motion, layer, and state tokens.
  • Token inspector shows definition, usage scope, and affected elements.
  • Shared-token edits require preview, impact list, apply, and revert.
  • Tailwind v4 semantic variables compile to portable CSS.
  • Client colors stay inside preview and swatches, never the ONE BOX shell.
08

Assets and media

Source, generate, inspect, place, replace, and trace every asset.
Asset safetyDirect importConditioning
  • Project image library with dimensions, format, performance, source, and rights metadata.
  • Upload, generated asset, approved library import, replacement, placement, and download.
  • Direct client asset import and unified lineage are proposed.
  • Reference-conditioned generation remains constrained by provenance and approval.
  • Candidate hashes bind the exact asset bytes under review.
09

Motion and interactions

Author behavior through a serializable motion schema.
Bounded motion
  • Entrance, exit, hover, focus, scroll, and timeline presets.
  • Duration, delay, easing, transform, trigger, replay, reset, and remove controls.
  • Preview and diff show the behavior before acceptance.
  • No arbitrary JavaScript. Motion stays serializable, validated, and removable.
  • Reduced-motion fallback, cleanup, keyboard parity, and touch behavior are mandatory.
10

AI assistant and composer

Turn natural language into reviewable, typed proposals.
Selection scopedResearch agentVoice
  • Persistent composer works with a selection or the whole candidate.
  • The assistant proposes typed mutations, then the designer previews, diffs, and applies.
  • Research-grounded suggestions can attach source cards without self-applying changes.
  • Assistant state is reachable from every tool and survives drawer changes.
  • Voice input and an adaptive toolbelt remain future candidates.

12

History, versions, and checkpoints

Make every meaningful change reversible and attributable.
Undo and historyUnified checkpointsCandidate identity
  • Undo, redo, Escape, cancel, and focus restoration.
  • Immutable candidate hashes connect preview, client lock, qualification, and release.
  • Version history shows actor, mutation, affected gates, result, and timestamp.
  • Unified site checkpoints, diff, and restore are proposed.
  • Restore reruns required gates and invalidates approval when visible output changes.
13

Quality and diagnostics

Run the smallest safe checks during design, then the full suite before release.
Gate routingQualification classesIssue navigator
  • Capability-to-gate matrix chooses affected checks after each edit.
  • Checks cover copy and evidence, assets, layout and tokens, motion, CTA, structure, and accessibility.
  • Unknown or mixed changes run the full suite.
  • Issues are classified as automatic repair, designer proposal, or release blocker.
  • A contextual issue navigator links findings to stable element IDs without weakening gates.
14

Accessibility, keyboard, and safety

Treat safe operation as part of the editor, not a final check.
Fail-closed boundaries
  • Keyboard operation, focus order, semantics, contrast, reduced motion, and touch targets.
  • Consistent empty, loading, error, unsupported, and rejected states.
  • Origin-checked, data-only messaging between Canvas and the preview iframe.
  • URL, file, path, upload, and untrusted-content validation.
  • No arbitrary executable code enters Page IR, prompts, candidates, or mutations.

15

Client review

Collect feedback against one immutable candidate.
Adjacent surface
  • Private, expiring, revocable candidate link.
  • Responsive preview without Canvas mutation controls.
  • Comments anchored to stable IDs, with resolved and unresolved state.
  • Request changes or approve this exact version.
  • No general client account is required for v1.
16

Agency qualification and SEO

Turn a locked design into a release-ready package.
Separate qualification
  • Visual, accessibility, content-truth, SEO, performance, functionality, privacy, security, appointment, and deployment readiness.
  • Technical SEO compiles deterministically from approved facts.
  • The system never invents claims, locations, services, credentials, or structured data.
  • Repair, proposal, and blocker queues feed back into Canvas.
  • A client lock is bound to the exact candidate under qualification.
17

Deployment and monitoring

Release an immutable bundle, verify it publicly, and preserve rollback.
Release-owned
  • Release-owner approval follows qualification.
  • Immutable bundle deploys to preview before production alias promotion.
  • Public-origin checks verify domain binding, rendered output, health, and appointment behavior.
  • Atomic promotion, last-known-good rollback, and post-release monitoring.
  • Canvas displays release status but never writes directly to live production.

Agent Studio and model router

Switch models and efforts without losing project context.
Owner-requested expansion
  • `Auto` routing plus direct selection of connected models such as Kimi K3, Fable 5, GPT-5.6 Sol, Gemini Flash, Grok, and local models.
  • Capability-aware effort menu shows only values supported by the selected model.
  • Pin per thread, override per turn, or compare two to four routes side by side.

  • Every turn records actor, provider, model, effort, tools, cost identity, and result.
  • Local subscription, agency cloud, and local-model execution lanes remain visibly distinct.
20

Skills and slash commands

Bring design, research, planning, motion, and audit capabilities into the composer.
Manifest-driven
  • Searchable `/design`, `/plan`, `/research`, `/copy`, `/seo`, `/motion`, `/audit`, and `/ship-check` commands.
  • Each skill declares inputs, models, efforts, tools, readable and writable scope, cost class, artifacts, and acceptance checks.
  • The invocation card shows selected scope and expected output before the run.
  • Skills create proposals and receipts. Candidate mutations still use preview, diff, typed apply, and gates.
  • Versioned skill results remain attached to the project and can feed later plans.
21

Plan workspace

Turn conversations into traceable PRDs, decisions, and scheduled work.
Conversation to execution
  • Meeting and chat extraction separates decisions, open questions, requirements, and tasks.
  • PRD sections carry requirement IDs, sources, owners, acceptance criteria, dependencies, and implementation boundaries.
  • Version diff, comments, suggestions, and immutable approvals.
  • Tasks support human or agent owners, due dates, recurrence, dependencies, model, skill, effort, cost cap, and completion evidence.
  • Scheduled agent work rechecks permissions, prerequisites, and source versions before it starts.

Remote agency workspace

screenshot-to-code adapted

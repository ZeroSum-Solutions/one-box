The library correctly keeps ONE BOX as base, one immutable layout authority per run, proposal-only model output, browser REJECT until EB-001–EB-021, GSAP/appointment/provider stops, and no implementation authorization. It must be revised before acceptance because operating-environment draft work is scheduled as if authorized, retained Electron/E0 shell is not consistently blocked by EB-001, T4 freezes the rejected E4.0–E4.7 decomposition, E7 React/ExperienceModule targets collide with Page IR static-site authority, and the starred/technology catalogs disagree on dispositions, phases, and Adopt vs Needs-license-review.

## Base project assessment

The retain-ONE-BOX decision is supported by the supplied comparison and by Page IR constraints. Puck is correctly held as a behind-IR interaction experiment, GrapesJS as HTML/CSS-authority conflict, Webstudio as AGPL plus alternate document model, Onlook as file/code ownership conflict, Craft.js as extra editor state (maintenance claim is not evidenced here), and OpenPage as immature direct-output authority. No supplied artifact shows an external editor that preserves candidate identity, typed mutations, and one layout authority per run. Do not re-platform.

## Star coverage assessment

The relevance pass is metadata/README triage, which the report itself says is not a source or security audit. Treat only a reconciled shortlist as planning input.

## Accepted decisions

- Retain ONE BOX as the base project; Puck, GrapesJS, Webstudio, Onlook, Craft.js, and OpenPage are not replacement foundations.
- One immutable layout authority per run: page-ir-v1 or guarded template-v1; never merge or switch inside a run.
- Models emit typed proposals only; deterministic compile, gates, candidate identity, and human approval remain authoritative.
- Embedded browser stays REJECT / NOT_AUTHORIZED until EB-001–EB-021 are closed, starting with hostile-page isolation.
- GSAP visual motion authoring is stopped pending written consent or license review.
- Yjs/CRDT limited to draft PRDs, notes, comments, cursors, and awareness; no CRDT merge of Page IR, approvals, or release state.
- P5 Release Orchestrator owns publishing; Instatic is a subordinate protocol after P1/P3/P4 and explicit P5 authorization, with no E7 publishing authority.
- Production provider selection is only at P6; appointment implementation remains unauthorized until separate acceptance.
- ST-WebAgentBench stays outside the offline corpus and requires a separately authorized sandboxed integration.
- AGPL/GPL sources (Webstudio, Firecrawl, Plane, OpenMontage, ComfyUI) and CloakBrowser anti-detection are rejected for code reuse.
- Catalog entries and the technology roadmap authorize no dependency or implementation by themselves.

## Residual risks

- Adopt/Adapt labels will be read as dependency authorization despite catalog disclaimers.
- Metadata-only starred triage will be treated as a source or security audit.
- Community model conversions and trust_remote_code revisions can drift after T1 pins if upgrade policy is not enforced.
- ExperienceModules can reintroduce executable site authority even if React is struck as a compiler target.
- Draft operating-environment product promises (cloud identity, Auto routing, client rooms) will pull work ahead of website Track A.

## Summary

Single-pass adversarial planning audit of the Release 1 contract and compatibility matrix, performed as the user-authorized Opus 5 OAuth fallback (Grok 4.6 timed out; this is NOT Grok evidence and is model input only). Filesystem and shell tools were disabled in this session, so the supplied packet bytes could not be re-hashed against the repository: the exact target aggregate SHA-256 (b8c7f6fa07b1c6dc1d6a3700f4e5219b14fa373c80df808b2846c610e878d636) and the two per-file SHA-256 values are UNVERIFIED, and the aggregate hashing method was not specified. The review therefore treats the inlined bytes as untrusted evidence reviewed as given. Overall the packet is a strong, unusually disciplined planning artifact: the journey is genuinely narrow, immutability and stale-invalidation language is consistent, provider neutrality holds (no vendor is named as selected), and the refusal to invent numeric quality targets before a frozen baseline protocol is correct and repeated consistently in both files. However, the closed journey is not closed at its two most safety-critical seams. Release approval binds the qualification receipt and bundle hash but never binds the client lock, so a repaired/requalified candidate can reach public release without a current client approval; release revocation is used as a fail-closed input in four places but is never produced, owned, or typed by any phase or actor; sections 3.7 and 3.10 carry no stop condition despite section 3 asserting every phase has exactly one, leaving rollback-revalidation failure and the adapter's authorization to promote a prior release undefined against invariant 7; the monitor emits a "runtime downshift/block required" class whose remediation mechanism, executing actor, and permission entry do not exist in a static-only Release 1 with runtime pointer serving deferred; the matrix asserts owner roles and powers (review owner owning session revocation, monitor owner, performance owner, agency owner) that are absent from the contract's permission table; and the matrix requires automated accessibility/SEO/performance measurement with frozen tool versions while contract section 9 defers exactly that tooling class and neither unresolved-decision register records the toolchain decision. Six P1 findings and five P2/P3 findings follow. No P0 was found: the packet does not authorize implementation, deployment, providers, schema changes, invitations, or appointments, and the appointment boundary in section 2.4 remains non-activating and deferred. Verdict is REVISE; the packet is safe to iterate on but not yet a complete basis for implementation planning.

## Accepted strengths

- The Release 1 journey is genuinely narrow and phase-boundaried: intake freeze, evidence, generation/gates, core Canvas refinement, private client review, qualification, release preparation, provider-neutral deployment, public verification/monitoring, and rollback/re-delivery each have a stated input boundary and durable output.
- Immutable layout authority is handled well: exactly one of page-ir-v1 or template-v1 per run, immutable for the run, explicitly not repairable, migratable, or re-deliverable into the other authority (§2.1), and the matrix reinforces 'no fallback to template-v1' and 'never falls through to Page IR'.
- Stale invalidation is stated positively and repeatedly: §3.4 makes every applied change produce a new candidate identity, rerun gates, and invalidate prior client, visual, qualification, and release decisions; invariants 3 and 5 forbid inheriting status by filename, timestamp, similarity, or list position and forbid writes on stale expected revisions.
- Last-known-good behavior is consistent across §3.3, §3.8 Stop, §3.9 Stop, invariants 8, 9, and 11, and the matrix fail-behavior column: failures preserve the prior valid public release rather than producing a partial swap.
- Appointment separation is held: §2.4, §5, the §6 appointment control-plane row, invariant 14 (separate website and appointment release identities; a website rollback cannot reactivate appointment state), and the matrix 'Deferred media/appointment' row all keep classification, CTA leases, publication, monitoring, downshift, and HumanRepublish outside Release 1.
- Provider neutrality is enforced rather than asserted: no vendor is named as selected, provider identity is confined to adapter receipts and cannot become source, candidate, approval, or monitor truth (invariant 17), and the matrix requires conformance testing against a provider-neutral/fake adapter with explicit failure injections.
- The refusal to invent numeric quality targets is the strongest part of the packet: §8.1 freezes a reproducible baseline protocol (routes, device profiles, network, viewports, build mode, tool versions, repeated runs, variance separation) before any threshold, and the matrix performance/accessibility/SEO rows and unresolved list repeat the same discipline instead of smuggling in a score.
- Human authority is preserved against automation: models may propose, summarize, and diagnose but cannot verify, approve, publish, deploy, rollback, or change runtime state (§6), and the monitor is explicitly 'not a second release approver'.
- The exclusion list (§5) and later-release boundaries (§9) are specific and named — embedded browser/WebContentsView, CRDT/Yjs/Hocuspocus, LiveKit, screenshot-to-code, model marketplace, provider selection — which makes silent expansion detectable rather than a matter of taste.
- Both files carry an honest unresolved-decision register and a closing rule that no unresolved decision may be filled by a provider assumption, an AI output, a new schema field, or a benchmark-inferred target; the authority manifest correctly classes both documents as 'proposed' with implementationAuthorized false.

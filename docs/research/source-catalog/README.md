## Coverage

- All 133 repositories starred by the authenticated GitHub account were captured. The REST and GraphQL counts matched.
- The first relevance pass retained 107 entries and excluded 26 unrelated entries.
- A source and license pass narrowed the 107 relevant entries to 18 phase-specific references. The 18-item shortlist is the only planning disposition and phase authority in this folder.
- The wider GitHub pass covers editor, browser, collaboration, model-routing, reconstruction, quality, SEO, deployment, and desktop-packaging projects.
- The Hugging Face pass covers local multimodal models, OCR, grounding, visual and text retrieval, advisory evidence scoring, Apple-silicon runtimes, datasets, and hostile-content benchmarks.

## Rules for use

- A catalog entry is research evidence, not dependency authorization.
- For starred repositories, only the 18-item shortlist assigns planning dispositions and phases. The 107-item relevance report and its JSON fields preserve census and first-pass traceability; the technology integration matrix explains boundaries but cannot add, promote, or reclassify a starred source.
- A newly discovered repository or package receives its own candidate identity even when its product name resembles a cataloged source. The JavaScript Deep Agents SDK does not inherit the Python repository's source identity, disposition, license evidence, or phase decision.
- ONE BOX remains the base project. No catalog project may replace a run's immutable `page-ir-v1` or `template-v1` layout authority, candidate identity, guarded mutation path, approval, qualification, or release authority.
- Pin source and model revisions before any benchmark or adaptation.
- Preserve upstream license and attribution receipts. Mixed, missing, custom, or copyleft licenses fail closed.
- Model outputs stay typed proposals. They never become browser actions, raw HTML authority, approvals, or publication decisions.

## How 107 entries became 18

A relevant repository entered the shortlist only when all of these conditions held:

1. Current primary README, license, and targeted source evidence exposed a specific reusable pattern rather than metadata-level similarity.
2. The pattern could change a named ONE BOX architecture, protocol, gate, or dependency choice.
3. The source added a distinct pattern not already represented by a stronger or safer shortlisted source.
4. The pattern fit one exact authorized or gated phase without replacing Page IR, candidate identity, cloud authority, browser containment, or release authority.
5. Maintenance and operational signals were adequate for the proposed use, or the shortlist explicitly limited the source to learning.
6. Licensing permitted the stated use, or the shortlist failed closed as `Needs license review` with no code-level use.

Repositories stayed outside the 18 when they were duplicative, metadata-only matches, weaker implementation candidates, alternate authorities, operationally disproportionate, legally unclear without a unique architectural benefit, or useful only as general inspiration. Exclusion does not change the 107-item relevance census.

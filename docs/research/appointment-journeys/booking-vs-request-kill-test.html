The binary fails.

“Booking versus request” hides three materially different promises. The page shell can be shared. The completion contract cannot.

DentistryMed spasPhysical therapyResearch memo
Confirmed careReal inventory reserves a care or treatment visit.
Booked consultationReal inventory reserves a consultation. Care is not yet scheduled.
Appointment requestPreferences go to staff for acceptance, matching, or verification.

Contact-only is a fallback. Hybrid is a service/location/provider router that selects one of the contracts above—not a fourth success state.

The operating rule

Inspect inventory authority

Live scheduler, staff-confirmed workflow, or no scheduling authority.

Classify the actual reserved object

Treatment, clinical evaluation, consultation, class, or nothing yet.

Scope the mode

Service, location, provider, and new/returning status can change the route.

Generate truthful language

CTA, success state, analytics, and recovery must match the contract.

Verify the live endpoint

A label or scheduler vendor is not evidence of inventory.

Architecture verdict

Adopt one appointment-acquisition family with three non-interchangeable completion contracts. Run the classifier before copy or interface generation; run the live endpoint verifier after integration. Never infer a stronger promise from an indeterminate flow.

Not a freeze. This is a Grok-audited recommendation. Human approval is still required before ONE BOX adopts the playbook or schema.

## Boundary

This step defines threat boundaries and runnable, deterministic contract oracles. It
does not run or authorize a model, provider, credential, skill, tool, browser,
connector, persistence layer, collaborator, Page IR mutation, deploy, or release.
The evaluator imports only Node built-ins, reads a local synthetic fixture, produces
a bounded JSON result, and has no provider or network adapter.

Security conformance, quality evaluation, cost/capacity conformance, exact-model
advisory audit, independent human verification, and product authorization are
separate verdicts. None can substitute for another.

Run from the repository root:

```bash
node --test scripts/eval/obx-p180-contract-fixtures.test.mjs
node --experimental-permission --allow-fs-read=. \
  scripts/eval/obx-p180-contract-fixtures.mjs \
  --fixture docs/eval/one-box-program/fixtures/capacity-and-cost-fixture-v1.json
```

The four fixtures are synthetic/Internal, declare `providerCallsPermitted: false`,
and contain 27 literal-oracle cases. Cost/capacity, security, human-decision, and
apply-eligibility cases are physically separate and emit distinct lane receipts; no
aggregate PASS exists. The executable checks route/fallback, reserve/capacity/
compare/retry, context/skill/slash/canary/identity, proposal-HITL terminal decisions,
and completed non-authorizing proposal consideration.

The 18-test suite mutates fallback and compare-auto-apply oracles, validates all four
lane receipts, exercises fail-closed human cancellation, rejects malformed roots,
cases, IDs, evaluator names, data classes, oracles and JSON, and proves the executable
refuses to run unless Node denies network permission. `providerCallsMade` comes from
the evaluator's runtime metric and is required to remain zero. This is evidence about
this local evaluator only, never a future driver/provider.

## Fixture and oracle contract

Every blocking fixture must have:

1. a versioned closed schema and stable fixture ID;
2. synthetic data only, with no credential, customer content, raw prompt/response,
   repository secret, or provider object;
3. literal expected acceptance and reason code derived independently of evaluator
   implementation;
4. a closed lane ID, evaluator allowlist for that lane, unique case IDs, and one
   named evaluator per case;
5. deterministic output for identical bytes and runtime major;
6. fail-closed behavior for malformed root fields, unknown evaluators, duplicate
   IDs, invalid oracles, or provider-enabled mode;
7. a negative mutation test proving a forbidden case cannot pass by changing its
   oracle; and
8. one bounded machine-readable lane result that records fixture/lane IDs, counts,
   denied-network status, runtime provider-call count, and verdict without raw
   evaluated content; no cross-lane aggregate verdict is permitted.

A future canonical program-manifest update must pin the accepted fixture, evaluator,
runtime, command, expected result schema, owners, and hashes. This planning packet
does not change the frozen program manifest or claim that the current executable is
a blocking release gate.

## Evaluation lanes and non-substitution

| Lane | Question | Evidence | Blocking rule |
|---|---|---|---|
| cost/capacity conformance | Do route admission, reserve, hierarchy, compare, retry, queue, and capacity rules produce expected decisions? | `capacity-and-cost-fixture-v1` lane receipt | every literal oracle passes; fallback/auto-apply mutations fail; zero provider calls |
| security conformance | Can context/skill/permission/canary/identity escape cross a boundary? | `obx-p180-security-fixture-v1` lane receipt, fixed adversarial corpus, independent review | lane passes and zero unresolved BLOCK/HIGH/MEDIUM; canary leakage always blocks |
| human-decision conformance | Does one proposal-HITL decision terminal safely under acceptance, drift, rejection, or cancellation? | `obx-p180-human-decision-fixture-v1` lane receipt | never substitutes for a named human decision; only state-machine conformance passes |
| apply-eligibility conformance | Can only a current completed non-compare proposal enter non-authorizing guarded consideration? | `obx-p180-apply-eligibility-fixture-v1` lane receipt | direct Page IR apply and compare-arm proposal are denied; never performs apply |
| quality benchmark | Does an exact admitted route meet task-quality thresholds? | pinned benchmark manifest, blind cases, rubric, exact model/effort, repeated runs | cannot run or pass until a provider-connected route is separately authorized |
| exact Grok audit | Does `x-ai/grok-4.6` find contract gaps in each numbered step? | raw JSON audit receipt bound to current file bytes | advisory planning gate; never runtime, quality, security-verifier, or authorization evidence |
| independent security verification | Does a named independent human accept evidence and residual risk? | signed review with scope, hashes, findings, expiry | model self-review cannot satisfy it |
| product authorization | May exact implementation effects occur? | accepted scoped authorization in the authority manifest | only repository owner acceptance grants it |

No aggregate score can average away a security, privacy, receipt-authority, cost,
identity, or authorization failure. Missing evidence is `NOT_RUN` or `BLOCKED`, never
PASS. A quality win cannot override a failed security/cost lane, and a cheaper/faster
compare arm cannot become a default without a separate decision and authorization.

## Provider-connected evaluation prerequisites

Before any live evaluation is proposed Ready, a separate packet must pin:

- provider/service/model/version/effort and independent reported-identity check;
- accepted price snapshot, complete worst-case budget, capacity policy, region,
  transfer, retention, deletion, telemetry, and credential boundary;
- exact benchmark corpus rights/data classes, prompt/template/skill/tool/context
  hashes, randomization, repetition count, variance and threshold policy;
- provider-side idempotency or durable outbox/recovery evidence and ambiguous-billing
  reconciliation owner;
- canary placement/detection, injection corpus, output schema/size validators, raw
  payload isolation, and repository leakage scan;
- named Evaluation, Model/Skill Security, Budget/Operations, Data Protection, Job/
  Sandbox, and Independent Security owners; and
- kill/rollback conditions that do not depend on the provider/model/skill being
  healthy.

Passing provider-offline fixtures cannot waive any prerequisite.

## Acceptance criteria

`OBX-P180-S5` is acceptable only when:

1. every trust boundary names its authoritative inputs, untrusted inputs, forbidden
   crossing, fail-closed outcome, and owner;
2. TM-02/03/04/05/08/09/13 plus injection, replay, resource exhaustion, receipt
   forgery, and stale apply have preventive and detective controls;
3. the provider-offline fixture and evaluator run without credentials, network, new
   dependencies, product runtime imports, or provider calls;
4. all 27 literal oracles pass in four distinct lane receipts and all 18 executable
   tests, including negative sensitivity and malformed-input cases, pass;
5. evaluation lanes are separately receipted and no score, audit, or model output can
   substitute for security verification, human decisions, or implementation authority;
6. missing, stale, malformed, noncompliant, or unresolved evidence fails closed and
   raw secrets/content stay outside repository receipts;
7. future live-evaluation prerequisites are explicit and none is represented as
   currently satisfied; and
8. exact Grok 4.6 binds this step and executable artifact bytes and reports no
   unresolved BLOCK, HIGH, or MEDIUM finding.

Passing Step 5 adds planning and provider-offline evaluation evidence only. It
authorizes no provider, skill, tool, credential, persistence, runtime integration,
browser, collaboration, Page IR mutation, deployment, or release behavior.
